# Клиентский мод APEX

Показывает тир или звание бриджера игрока (цвета и подписи как на mc-apex.ru) над ником и в табе,
команда `/apex <ник>` выводит в чат карточку игрока. Ник ищется и по нику Minecraft, и по нику на сайте.
Данные берутся из публичного API сайта (`GET /api/mod/player/{query}`, `POST /api/mod/tiers`),
описание ответов: `docs/book/14-чат-мост-minecraft.md`.

## Устройство

```
core/            общая логика на Java 8, без Minecraft: HTTP-клиент, кэш, разбор ответа, форматирование /apex
forge-1.8.9/     Forge 1.8.9 (Java 8, сборка Essential Loom на JDK 17)
```

Один jar на все версии невозможен: у каждой версии Minecraft и каждого загрузчика свой API, поэтому
у каждой версии свой подпроект и свой jar. Подпроект подключает `core/src/main/java` как исходники,
вся логика, не связанная с игрой, живёт только в `core`. Новая версия = новый каталог с тонким адаптером
(команда, таб, значок над ником, перевод `ChatFormat.Line` в компоненты чата).

Версии: Forge 1.8.9 (готово). Fabric 1.21.x и 26.x - планируются отдельными подпроектами. Forge для 26.x
не рассматривается: там Fabric и NeoForge.

## Сборка (WSL)

Нужны JDK 17 и Gradle 7.6.x для `forge-1.8.9`:

```bash
cd minecraft-mod/forge-1.8.9
JAVA_HOME=~/dev/tools/jdk/17 ~/dev/tools/gradle-7.6.4/bin/gradle build
```

Готовый jar - `forge-1.8.9/build/libs/apex-mod-forge-1.8.9-1.0.0.jar` (в `mods/` клиента; файл с `-dev` - для среды разработки, не ставить). Jar в git не коммитятся.
Если сборка падает по таймауту `libraries.minecraft.net` - просто повторить, большая часть уже скачана в кэш Gradle.

## Если цвета тиров на сайте меняются

Палитра приходит с сервера (`ModPlayerService::TIER_COLORS`), мод её не хранит; менять нужно только бэкенд.
