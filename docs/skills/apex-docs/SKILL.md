# Документация APEX

В репозитории три документа, и у каждого своя роль. Ошибка — написать одно и то же
во все три. Правильно — держать один факт в одном месте в нужной плотности.

| Документ | Для кого | Плотность | Файл |
|---|---|---|---|
| **Книга** | разработчик | как устроено, с кодом и формулами | `docs/APEX-Книга.md` |
| **Руководство** | игрок | что нажать и что будет | `docs/APEX-Руководство.md` |
| **Памятки** | все, на бегу | одна тема — одна страница, только числа | `docs/APEX-Памятки.md` |

Исходники — тоже в репозитории, править нужно их, а не собранные файлы:

```
docs/book/*.md          главы книги (00–02 основные, 1x справочник, 8x–9x приложения)
docs/guide/*.md         руководство и памятки
docs/tools/             сборка: markdown → DOCX → PDF
```

Собранные `APEX-*.md` в корне `docs/` — **производные**. Их перезаписывает сборка,
руками не править.

---

## 1. Порядок работы

1. **Найти, что изменилось.** Не начинать с документов — начинать с кода.
2. **Проверить факт по коду.** Любое число — из константы, конфига или `Request`-класса. Не из головы и не из старого текста.
3. **Обновить источник** в `docs/book/` или `docs/guide/`.
4. **Прогнать сборку:** `node docs/tools/build.mjs`.
5. **Проверить PDF** — что раздел появился и не поехал.

Прочитать перед правкой: `docs/tools/README.md` — там про сборку и про занятые файлы.

## 4. Правила текста

**Числа — точные.** «Около 40» запрещено. Есть 40 — пиши 40. Не знаешь — иди в код.

**Перечисляемое — перечисляй.** Не «восемь артефактов», а таблица с названиями и ярусами. Не «несколько наград», а все значения.

**Обещания — только те, что срабатывают.** Если механика объявлена в enum, но не реализована — так и напиши: «объявлено, но не работает». В книге для этого есть раздел «Что в коде отсутствует».

**Одна мысль — одно место.** Формулу урона разбираем в книге, в руководстве пишем «атака третья подряд бьёт сильнее», в памятках — просто «серия бьёт больнее».

**Три регистра подачи:**

| Документ | Как писать |
|---|---|
| Книга | «Метод `forbidden()` возвращает причину или `null`» — с именами классов и фрагментами кода |
| Руководство | «Умение перезаряжается 3 раунда» — от лица игрока, без кода |
| Памятки | «Умение — перезарядка 3» — таблица, минимум слов |

**Не выдумывай UI.** Названия кнопок бери из вьюх `frontend/src/views/` и `components/`. Если не нашёл — пиши нейтрально: «кнопка на карточке товара».

## 5. Структура главы книги

Файлы в `docs/book/` именуются по префиксу, и префикс задаёт судьбу:

| Префикс | Что это | Нумерация |
|---|---|---|
| `00`–`02` | введение, бэкенд, фронтенд | `## N.` продолжается |
| `1x` | справочник по доменам | без номера в заголовке |
| `80`–`92` | приложения | `## Приложение X.` |

Сквозная нумерация `##` в книге непрерывна: 1–14 до справочника, 15–28 после.
Новая глава либо встаёт в справочник (без номера), либо добавляется в конец
следующего номера. Номера не переиспользовать — на них ссылаются
перекрёстные ссылки вида «см. главу 12».

Внутри главы держи порядок: зачем механика → как устроена → числа → что видит
пользователь → «что в коде отсутствует».

## 6. Сборка

```powershell
node docs/tools/build.mjs
```

Скрипт сам соберёт `APEX-Книга.md` из глав, затем сделает DOCX и PDF для всех
трёх документов. Подробности и переменные окружения — в `docs/tools/README.md`.

**Если PDF не обновился** — файл открыт в просмотрщике, Windows не даёт
перезаписать. Закрой его и повтори сборку. Если закрыть нельзя, собери мимо
через `$env:APEX_PDF_DIR` и перенеси готовые файлы в `docs/` вручную.

Проверка результата:

```bash
# PDF — это PDF, а не пустышка
head -c 5 docs/APEX-Книга.pdf     # должно быть %PDF-

# сколько закладок в PDF (навигация по заголовкам)
grep -a -c '/Title' docs/APEX-Книга.pdf
```

## 7. Чек-лист перед сдачей

```
[ ] все изменённые числа сверены по коду, а не по памяти
[ ] правка внесена в docs/book/ или docs/guide/, а не в собранный APEX-*.md
[ ] сборка прогнана целиком — node docs/tools/build.mjs, без ошибок
[ ] в PDF есть новый раздел (открыть и посмотреть, а не поверить логу)
[ ] оглавление и закладки не потеряли порядок
[ ] номера глав не задвоились и не пропустили
[ ] если механика не работает — это написано прямо
```

## 8. Частые ошибки

**Править собранный `docs/APEX-Книга.md`.** Перезапишется при следующей сборке. Источник — `docs/book/`.

**Дублировать числа в трёх документах по-разному.** Обновил награды — обнови все три и проверь, что числа совпадают.

**Забыть приложение при правке конфига.** Изменил `config/apex.php` — это автоматически Г.1 в книге, раздел 8/26 в руководстве и карточка 8 в памятках.

**Писать «восемь находок».** Перечисляй. Список короткий, а вопрос «какие?» возникнет сразу.

**Ставить обратные кавычки в заголовке главы.** Оглавление собирается из заголовков; в книге они уже стрипаются сборщиком, но в новом заголовке лучше обойтись без разметки.

**Забыть про занятые PDF.** Самая частая причина «а почему PDF старый» — он открыт в вьюере.

**Запускать CLI LibreOffice из WSL.** Он Windows-процесс и не найдёт свои модули
по путям `/mnt/c/…`. Сборку гонять из Windows: `node docs/tools/build.mjs`.

**Менять `build_book.mjs` без причины.** Порядок частей и приложений задан там; если добавляешь новую часть, добавь её и в `ORDER`/`TAIL`, и в `REFERENCE_INTRO`, если это справочник.
