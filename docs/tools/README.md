# Сборка документации APEX

Три документа собираются из Markdown в DOCX и PDF одним скриптом.

```
docs/
├── book/          главы книги — источник, править здесь
├── guide/         руководство и памятки — источник, править здесь
├── tools/         этот каталог: сборка
├── APEX-Книга.md         ← собирается из book/
├── APEX-Книга.docx       ← собирается из APEX-Книга.md
├── APEX-Книга.pdf        ← собирается из .docx
├── APEX-Руководство.*    ← из guide/Руководство-пользователя.md
└── APEX-Памятки.*        ← из guide/Памятки.md
```

Файлы `APEX-*.md` в корне `docs/` — **производные**. Правки в них пропадут при
следующей сборке; источники лежат в `book/` и `guide/`.

## Запуск

```powershell
node docs/tools/build.mjs
```

Скрипт делает всё по порядку:

1. `build_book.mjs` — склеивает главы из `book/` в `APEX-Книга.md`, расставляет
   заголовки частей и строит оглавление;
2. `build_docx.py` — верстает DOCX: обложка, оглавление, стили заголовков,
   таблицы, блоки кода, колонтитул с номером страницы;
3. LibreOffice Kit — конвертирует DOCX в PDF (закладки PDF строятся из
   заголовков автоматически).

**Почему Node, а не PowerShell.** Скрипт всё равно гоняет node (сборка книги и
CLI LibreOffice), а Windows PowerShell 5.1 читает UTF-8 без BOM как cp1251 —
кириллица в скрипте ломается, и вдобавок политика выполнения блокирует `.ps1`.
Один рантайм вместо трёх.

## Зависимости

| Что | Как ищется |
|---|---|
| Node.js | тот же, чем запущен скрипт (`process.execPath`) |
| Python + `python-docx` | `APEX_PYTHON` → рантайм DSH → `python` из PATH |
| LibreOffice Kit CLI | `APEX_LO_CLI` → путь рантайма DSH → PDF не собирается |

```powershell
$env:APEX_PYTHON  = 'C:\путь\к\python.exe'
$env:APEX_LO_CLI  = 'C:\путь\к\libreoffice-kit\lib\cli.js'
$env:APEX_PDF_DIR = 'C:\Users\я\Temp\pdf'
```

`APEX_LO_CLI` — Node-CLI из LibreOffice Kit, вызывается как
`node cli.js convert --input x.docx --output x.pdf`. **Запускать его нужно из
Windows**: из WSL он не находит свои модули по путям `/mnt/c/…`.

## Отдельные шаги

```powershell
# только пересобрать книгу из глав
node docs/tools/build_book.mjs

# только DOCX из конкретного исходника
python docs/tools/build_docx.py <исходник.md> <результат.docx> "<подзаголовок обложки>" "<подпись колонтитула>" [flow]

# только PDF
node <cli.js> convert --input <файл.docx> --output <файл.pdf>
```

Пятый аргумент `flow` включает «плотный» режим: главы идут подряд, без разрыва
страницы перед каждой. Так собираются руководство и памятки — там главы по
1–2 абзаца, и с разрывами полстраницы пустует. Книга собирается без `flow`:
её главы длинные, и каждая начинается с новой страницы.

## Как устроен `build_docx.py`

Разбирает Markdown на блоки и верстает их в Word:

| Markdown | В документе |
|---|---|
| `# Часть …` / `# Приложения` | заголовок части, с новой страницы |
| `## …` | глава, с новой страницы (кроме режима `flow`) |
| `### …` | подраздел, без разрыва |
| `\| таблица \|` | таблица с рамками и подсветкой шапки |
| ` ``` код ``` ` | моноширинный блок с полосой слева |
| `- список` / `1. список` | маркированный или нумерованный |
| `**жирный**`, `` `код` ``, `[текст](url)` | форматирование внутри абзаца |

Заголовки — **настоящие стили Word** (`Heading 1–3`), поэтому LibreOffice
строит из них закладки PDF: по книге можно прыгать через панель навигации.

## Грабли

**PDF не обновляется, сборка падает с «файл открыт в просмотрщике».** Windows
не даёт перезаписать открытый PDF. Закрой и повтори. Если закрыть нельзя —
собери мимо и подмени вручную:

```powershell
$env:APEX_PDF_DIR = 'C:\Users\я\Temp\pdf'
node docs/tools/build.mjs
# затем перенести APEX-*.pdf из этой папки в docs/
```

**Заголовок части остался один на странице.** У части и у следующей главы
одновременно стоял разрыв. В `build_docx.py` это учтено: первая глава после
заголовка части идёт на той же странице.

**В оглавлении видны обратные кавычки.** Оглавление собирается из заголовков;
разметку из них надо убирать (сборщик это делает для книги, но не для
произвольных заголовков в новых главах).

**Дублируется заголовок «Приложения».** Его ставит первое приложение
(`90-приложение-схема.md`, у него в `TAIL` указана часть `Приложения`).
Остальные приложения идут с `part: null` и своего заголовка не имеют.
